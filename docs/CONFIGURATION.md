## 模型连接

可以保存多个模型连接，设置默认模型，并在聊天面板选择本轮使用的模型。

| 字段 | 如何填写 |
| --- | --- |
| 显示名称 | 便于识别的本地名称，不影响服务端请求 |
| Provider | 与接口协议匹配的适配器，不只看服务商品牌 |
| 模型名称 | 服务商文档给出的模型 ID，不能用自己起的显示名称替代 |
| 服务地址 | 服务根地址；自定义网关按其说明设置 |
| 请求路径 | 可选；避免与根地址重复拼接路径 |
| API Key | 从服务商取得；TuGo 不提供密钥或额度 |
| 上下文 / 最大输出 | 按模型实际规格设置，填写更大数值不会提升服务端限制 |
| 支持视觉 | 仅在模型和接口确实接受图片输入时启用 |

源码提供 OpenAI-compatible、OpenAI Responses、Anthropic 和 Google/Gemini 等适配器。协议测试不等于所有模型实测通过；自定义网关的工具调用、流式响应和视觉兼容性需要实际测试。

“测试”会进行网络请求。失败时依次检查错误详情、模型标识、URL/请求路径、凭据、余额与限流。不要为了绕过证书错误禁用 TLS 校验。

## 视觉模型与非视觉模型

“支持视觉”是**当前模型连接**的能力开关，不是让所有模型自动获得识图能力。它必须同时满足：模型本身支持图像输入、所选 Provider/网关能透传图像、服务端账户允许使用该能力。启用错误时，实际请求仍可能被服务端拒绝。

| 场景 | 开启视觉 | 未开启视觉 |
| --- | --- | --- |
| 聊天中附加 PNG/JPEG/WebP 等图片 | 图片作为模型的视觉输入 | Runtime 会拒绝本轮图片理解请求，避免假装模型看到了图片 |
| Agent 检查画板的实际渲染效果 | 可以创建受控画板截图并调用图片查看能力 | 不提供截图/图片查看工具，只能根据节点、连线和文字等结构化状态判断 |
| 复刻截图、白板照片或流程图图片 | 可以识别布局、形状、可见文字和视觉层级，再重画为可编辑对象 | 需要你先提供文字版说明、节点清单或 Mermaid；模型不能从图片中提取内容 |
| 文本、代码、可提取文字的文档 | 可使用 | 仍可使用；这不依赖视觉 |
| 成本与上下文 | 图片会增加服务商的上下文和可能的计费 | 不发送图片输入，通常更省，但不能完成看图任务 |

非视觉模型并不等于“不能画图”：它很适合根据明确需求、Mermaid、表格、节点/连线清单生成和整理图表。视觉模型也会看错小字、模糊图片或复杂截图；对关键内容应提供文字约束并在结果中人工核对。

如果一张图片只是想作为画布背景，不需要开启视觉；使用工具栏“添加图片”即可。若希望 AI 理解这张图片，请把图片作为聊天附件发送，并在本轮选择已经验证过的视觉模型。完整操作见 [案例与提示词](EXAMPLES.md)。

## 外部 MCP

在“设置 → MCP”新增连接：

- 远程连接：选择与服务器匹配的 Streamable HTTP 或 SSE，填写完整端点；HTTP/HTTPS 是 URL 协议，不是额外一种 MCP 传输。
- stdio：填写可执行命令、参数（每行一个）和环境变量。外部 MCP 需要的 Node/Python 等依赖由用户另行安装，不能假定 Electron 自带运行时能启动任意 MCP。
- 保存并测试连接，确认工具列表，再选择允许使用的工具和是否绑定到画板 Agent。当前没有 MCP OAuth 自动登录。

敏感名称匹配的 Header/环境变量会转为本地凭据引用；不要把密码放在 URL、命令参数或未识别的任意字段中。允许全部工具前检查权限，stdio 服务以本机用户权限运行。TuGo 内置附件工具的路径限制不代表第三方 MCP 也受到同样限制。

## Skills

在“设置 → Skills”查看内置 Skills，导入或创建自己的 Skill，通过编辑助手维护说明与资源。在画板的 Skills 入口管理可用范围，并可在聊天中用 `@` 选择可用 Skill。

Skill 是指导模型如何工作的说明与资源，不是新的模型，也不保证结果正确。导入第三方 Skill 前检查内容；不要在资源中放入密钥。

## 主题、语言与图狗游标

“设置 → 外观”可选择浅色/深色/跟随系统、显示语言和游标造型。图狗是默认绘画游标。

语言选项：英语、简中、繁中、日语、韩语、西语、法语、德语、巴西葡语、俄语。自动模式从系统语言偏好列表中选择支持的语言，没有支持项时使用英文。部分界面仍未完全本地化。

内置 Agent 提示词按简中、繁中、英文分流；非中文界面使用英文提示词。用户输入、历史消息、画板内容和第三方返回的错误不会因此自动翻译。

## 数据

配置和数据在“设置 → 数据与恢复”显示的目录中。不要将目录、密钥文件或诊断包提交到 Git。备份方式见 [备份与恢复](DATA_RECOVERY.md)。
