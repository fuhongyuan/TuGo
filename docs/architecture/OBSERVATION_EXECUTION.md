# S4 工具执行观察与恢复

状态：S4已验收，见OpenSpec证据记录。本页描述执行控制器的实际接入边界；不等于S5上下文投影、S6领域迁移或S7整体交付已完成。

## 执行与归责

`runtime.ts`中模型发起的真实工具调用路径现在经过`executeObservedTool`；复用原`run_tool_calls`账本和检查点，不创建第二套Agent Loop或重试账本。内部主动board_observe调度仍由旧机制承担，通用化迁移与整体协调属于S7，不宣称已经覆盖所有内部控制动作。批次内固定契约，调用只由pending→running的领取者执行；重复ID返回已有结果，不再一律显示成功。

每个调用只有`tool-executor`作为自动恢复责任方。统一budget含最大attempt数和截止时间，invoke与query_status均计数。默认最多3次、时间受工具预算和Run剩余预算共同限制。每次实际尝试前写入检查点/执行事件并await数据库flush；持久化失败、取消或剩余时间耗尽时不发起新调用。

受控内部适配器若需额外尝试，必须使用`AttemptContext.beginInternalAttempt(id)`，它共享同一budget并先持久化；不能另建隐藏重试循环。当前未修改或信任外部MCP服务内部行为，无法观测的远端重试不被宣称可精确计数。

## 可信契约与退避

`RuntimeExecutionServices`是宿主构造时注入的配置，不接受模型参数或MCP自报注解。默认平台仅将明确实现的read-file/web-fetch/web-search标记为只读；其他工具保守视为可能有副作用。

- 参数、认证、权限、未知错误不盲目重试。
- 可安全恢复的暂时错误/限流才进入退避，Retry-After为等待下限，超过总预算则升级。
- 没有可信契约，不自动重试。恢复不会因为错误文本看起来像429就猜测写操作未执行。
- 模型服务本身已有的流式重试，与此处工具调用预算属于不同调用边界，不叠加成工具内部重复执行。

## 未知写结果与回执

写入超时不等于未执行。若宿主提供可信`queryStatus`，传入稳定runId/callId和同一预算查询回执：

1. succeeded且有实际result：返回该结果，不再写入。
2. not_started：允许预算内重新尝试。
3. unknown、查询失败或无查询保证：升级，账本记uncertain，不直接重放。

宿主的回执服务必须自行验证身份、目标和执行ID。现有TuGo画板桥接尚未注册可证明的通用操作回执查询，因此默认遇到未知写结果仍保守升级；不能把测试注入的回执能力说成生产画板已具备。

## 取消、晚到和重启

预取消的调用不开始执行；持久化过程中取消也不会越过调用前屏障。执行中取消只代表停止等待，不声称远端副作用被撤销。已确认成功但结果记录失败，保留成功执行事实，禁止当作失败重放。

桥接层对已发送但取消/超时的请求保留有界墓碑（最多256项、至少60秒有效期）。晚到响应仅记审计，不恢复旧调用、不重写终态、不重新应用业务修改。完整晚到载荷通过S3存储写入evidence-v1，日志只存引用；敏感内容/配额/写入故障则记录不可取回原因，不把完整证据缺失说成成功验收。收到的回执仍是历史事实，当前领域状态validity保持unknown。

正常关闭会等待已开始的晚到证据写入；进程强制退出或墓碑过期后无法再接收的响应仍保持uncertain。重启复用原账本恢复，不自动重放running/uncertain写操作；不承诺分布式exactly-once。

## S7.4跨层恢复与兼容验收

取消后，宿主写结果可能仍晚到：晚到回执作为独立证据保存，不升级已取消调用为可重放，也不再次应用业务。完整Runtime重新启动不自动续跑中断run；调用账本保持uncertain，beginToolCall拒绝相同run/call重复执行。runActionBudget随checkpoint保存，重启保留used/deadline/byLayer；新run使用新身份和预算，不冒充原run的自动恢复。

本轮组合测试覆盖完整Runtime停止/启动、晚到结果证据、相同call拒绝、无启动host调用、预算保持；旧模型/MCP绑定/Skills/提示词联合fixture重启前后相等，另有模板升级保留用户内容及授权/传输/附件回归。恢复意味着保留事实与要求重新观察，不承诺跨不同callId的新请求具备分布式exactly-once。

接口为加法：旧checkpoint没有runActionBudget时首次新run创建；旧观察缺失session/scene/范围等身份可保留历史，但不能用于当前验收。只读观察不会把未知写结果改成未执行；取消后的新尝试必须重新获得可信授权。旧自定义模型/MCP/Skill/Prompt不被本轮新字段覆盖；测试使用隔离fixture，不读取真实凭据，不等同S8生产数据副本/安装包验收。

### 取消后的前端投影隔离

流已经settled后，即使旧事件分发器已把回调排队，也不能继续推送文本/运行状态；晚到start回执只用于取消旧run，不能调用onRunId绑定到新的本地任务。会话协调器以最多128条终态引用防止旧pending快照覆盖已结束消息，不新增消息、不跨会话复用，归一化后的会话也用于持久化。单元模拟晚到回执/旧回调及旧会话快照；UI每轮先确认真正终态和composer空闲，再显式测3轮取消/队列调度。该缓存为前端临时防线，不替代Runtime账本和持久状态。
