# Kernel / TuGo Package / Platform 拆分实施方案

状态：2026-08-31 实施基线。替代归档的 SDK v0.1 讨论稿；测试结果在交付时另行记录，本文不是已通过声明。

## 1. 本次交付

将当前 TuGo 拆为三个真实职责单元：Node/TypeScript Agent Kernel、TuGo 官方应用包、负责装配和宿主服务的平台。交付可运行的 macOS Apple Silicon 桌面包，保持现有 TuGo 数据、凭据、模型、MCP、Skills、画板和会话可用。

首版只加载官方可信应用。支持桌面宿主和可测试的无界面 Node 宿主；云部署复用 Node 核心，不包含公有云多租户运营系统。依赖 UI 的工具必须明确声明，不能宣称断开界面后仍可执行。任意第三方市场、付费分发、不可信代码沙箱、跨端自动迁移、运行中热替换均不属于本轮。

## 2. 职责及依赖

| 单元 | 职责 | 禁止 |
| --- | --- | --- |
| Kernel | 运行循环、状态、上下文预算、工具调用记录、事件、取消；消费类型化端口 | 直接创建数据库、依赖 Electron、识别 TuGo/board/PPT 工具 |
| TuGo Package | 画板领域工具、参数规范化、提示词、图形检查、成果处理、UI、业务初始化 | 复制 Agent 循环；成为核心的编译依赖 |
| Platform | 应用清单校验和装配、存储/模型/MCP/Skills 适配、进程与 UI 通信、配置/凭据和生命周期 | 把所有应用视为可以读写全部用户资源 |

通用能力组件属于平台可装配能力，不是第四个产品。共享协议可以独立成模块，但不新增运行服务。源码可以在同一仓库维护，兼容旧导入入口不代表保留旧执行实现。

## 3. 首版契约

- 应用声明：稳定 ID、版本、协议版本、UI/运行入口、默认资源、所需宿主能力。
- 应用贡献：工具规范化/执行、上下文、结果处理、领域状态与初始化；工具必须注册才能执行，冲突拒绝。
- 运行装配：平台选定应用与工作区、模型、工具和扩展，保存配置摘要；运行中不替换贡献。
- Kernel 端口：运行存储、模型访问、工具执行、上下文与结果扩展、通用事件；不暴露平台全量管理接口给产品扩展。
- UI/平台契约：保留现有 TuGo facade 作为迁移适配，应用服务通过宿主注入；管理能力与运行能力分离。
- 生命周期：启动失败清理、重复启动防护、停止与取消、明确中断语义。不新增未经实现的自动恢复承诺。

特殊节点以受约束的上下文贡献、工具和结果/完成扩展表达，不引入任意可改内部状态的工作流引擎。第一方进程隔离不是恶意代码安全沙箱。

## 4. 数据兼容是发布门禁

1. 保持生产 `TuGo` 应用名、`com.agentplatform.tugo` 标识及原 userData 路径；架构品牌变更不与存储迁移混做。
2. 保留 App/Runtime 两个物理数据库和资源 ID；先隔离访问职责，不同时换数据库或合库。
3. 保持本地凭据派生规则兼容；不得将真实密钥复制进代码、日志、测试报告或安装包。
4. 只在用户数据副本中验证；备份包含数据库、附件、配置和加密凭据。副本路径不同导致的密钥派生差异必须显式处理，不能误报丢失。
5. 应用默认资源安装保留用户编辑；旧 Skill、模型和 MCP 配置不可被重新 seed 覆盖。
6. 生产目录存在有效配置时直接沿用，不弹首次配置流程。开发数据与生产数据不得静默覆盖合并。
7. 数据快照格式继续识别 TuGo。卸载/禁用应用与删除用户数据不是同一操作。

## 5. 执行顺序

| 阶段 | 产物 | 门禁 |
| --- | --- | --- |
| A 基线 | 方案、旧稿归档、Git 基线、新分支、依赖修复 | 原版测试结果有记录；真实数据仅只读核对 |
| B 最小三件套 | Kernel 注入式执行、TuGo 注册包、平台装配根 | TuGo 工具闭环和第二个非画图应用均使用同一循环 |
| C 完整归位 | 产品分支/seed/工具处理迁出；UI 包入口；平台宿主入口 | 自动依赖边界检查；无 TuGo 核心运行；旧接口回归 |
| D 数据与异常 | 用户配置副本兼容、调用/取消/崩溃测试 | 不重复业务写操作；旧配置和自定义内容保留 |
| E 交付 | 构建、单元/集成/桌面测试、macOS 包与包内运行验证 | 实际命令通过；签名性质和已知限制明确 |

从最小闭环纵向拆分，不先搬完所有目录再接回。产品业务后端可先保留 Renderer 适配；无界面宿主只暴露已实现能力，对缺失的 UI 能力启动校验或明确拒绝。完整云端画板渲染另需在能力矩阵中说明，不以服务进程能启动替代产品验收。

## 6. 必须增加的验证

- 不加载 TuGo 的 Kernel 可以执行最小非画图任务，新增工具无需改循环。
- 包 ID/版本/能力校验、重复注册和不支持能力失败；实例之间状态不串用。
- TuGo 提示词、画板绑定、质量/截图/PPT 结果行为保持。
- 旧模型、MCP、Skills、用户修改提示词、线程和附件在新实现中可读。
- 核心不导入平台实现、Electron 或 TuGo；平台通用装配不内嵌产品分支。
- 本地既有 E2E、Worker/Renderer 故障、数据恢复和打包态测试。
- 新包使用原数据身份；副本检查凭据可解密但不输出内容。
