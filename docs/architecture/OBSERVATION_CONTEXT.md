# 上下文观察与预算投影（S5）

状态：S5.1–S5.3已验收；最终批次全量493项/兼容85项/构建通过，证据以OpenSpec执行记录为准。完成S5不代表全部观察体系或发布已完成。

## 已接入的调用路径

```text
检查点历史 + 系统契约 + 工具定义 + 附件 + 输出预留
  → beforeModel 中间件补充计划、Skills 与约束
  → Kernel projectContext 预算检查
      ├─ admitted：保留原消息/工具/附件，调用原配置模型
      └─ rejected：记录原因并有界停止，不发送该次请求
  → 重试追加运行时指引后，再检查一次预算
```

S5.1时同一门禁覆盖历史摘要、会话标题两个辅助调用。**S5.2已停用主循环的有损历史摘要调用**（见后文）；标题继续经过同一门禁，失败不影响主任务。

Kernel 的 `contextProjection.ts` 只依赖契约和预算函数，不导入文件系统、Electron 或画图业务。Runtime 负责装配配置与写入现有 journal，不另建 Agent Loop。预算检查本身不修改历史、不截字符串、不删工具或用户约束、不换模型。

## 估算及决策

`contextBudget.ts` 统一提供分项估算与旧触发启发式；`projectContext` 进行严格配置校验和准入判断。

- 文本：UTF-8 字节上界估算，含消息字段、工具调用 ID、原始参数、推理/provider metadata、工具定义及协议开销；比旧字符数除 2.5 更保守。
- 媒体：遵循 Provider 的附件绑定规则；同一图片被多条历史消息引用时逐次计入，旧格式无绑定只落在最后用户消息，未发送的附件不计入。图片默认每次预留 16,384 单位。
- 输出：使用实际 `maxOutputTokens`，与输入共同占用窗口；主请求、摘要和标题分别核算。
- 安全空间：默认仅使用窗口的 95%，不得在预算检查之后补进模型指引；重试每次重新核算。

这是跨 Provider 的**保守估算，不是厂商 tokenizer 或图片实际 token 的保证**。图片估算及非精确 tokenizer 限制写在决策中；暂不根据真实用量自动校准或切换模型。较保守的文本估算可能提前拒绝本可容纳的请求。

已存在的模型 `extra_config` 承载可选参数，不重写用户配置：

| 参数 | 默认 / 校验 |
| --- | --- |
| `context_window` | 沿用模型配置；正整数，由现有模型保存校验及投影校验共同检查 |
| `max_output_tokens` | 沿用模型配置及实际调用预留 |
| `context_safety_ratio` | 0.95；允许 0.5–0.98 |
| `image_token_reserve` | 16384；至少 2048 的整数 |

无效配置直接拒绝，不回落到更宽松预算。`ContextProjectionError` 保留结构化决定；不附带原文或秘密。

## 追踪及脱敏

现有 journal 事件 `context.projection`，actor 分为 `agent_loop`、`summarization`、`session_title`，携带 run/thread/loop 关联。每次实际模型尝试之前记录；预算不足也记录被拒原因。

仅保存纯计数 DTO：`estimatedUnits`、`safeBudget`、`headroomUnits`、`imageReserve`、`partitions`（system/history/toolDefinitions/media/outputReserve/framing/mediaOccurrences）、估算版本、配置及限制。单位为估算 tokens，不包含模型文本、附件 Base64、原始工具结果或 API 密钥。内部 `*Tokens` 类型字段映射为 DTO 是为了避免既有凭据脱敏器把计数误删；**没有放宽公共脱敏规则**。

## S5.2：关键证据与可恢复集合

本节替代前文 S5.1 时的有损摘要现状说明：实际主循环不再调用模型生成历史替代摘要，也不再用 fallback 摘要替换历史。原有用户摘要字段保留，不伪造或恢复旧版本已经丢失的细节。用户的 summarization 配置不被删除或覆盖，但不再授权有损替换历史；安全规则优先，固定采用以下投影。

### 数据路径

```text
工具实际完成 → 执行器确认事实 → modelResultContent
  ├─ 小结果或无明确集合：完整内容
  ├─ 大结果有 rows / observation.findings：S3存原始结果 → 受控引用视图
  └─ 存储失败：完整结果 + 不可用原因 + 已执行事实，不请求重放
引用视图 → runtime_read_evidence → 同会话授权注册表 → S3范围校验 → 有界分页
完整历史（只替换上述工具内容，不删消息）→ 配对校验 → S5.1安全预算门禁
```

自动观察结果也采用相同结果投影，不再通过旧的前五项摘录丢弃其它元数据。自动观察的触发/去重及领域效力仍属 S6/S7，不在本项冒充完成。

### 最小证据及透明性

- 只把两种明确集合 `rows`、`observation.findings` 外置；原字段显示空集合，旁附 `referenced_collections` 声明，明确未呈现明细而非空业务结果或已交付汇总。Root 数组、任意长文本、Skills/说明、未知字段不推断为可压缩内容。
- 标量、目标约束、pending事项、检查未知项、版本元数据、原始声明的完整阻断/警告数量、处理/修复记录完整保留；规范化记录保留前三条问题和完整计数、存储问题数量及恢复入口。最小元数据本身过大就停止，不继续删除字段。
- 执行事实只由执行器提供；旧观察结果通过保守适配器，`validity=unknown`（或stale），不会因原始 `passed` 建立有效通过。引用的数据不是实时画板验收证明。
- 原结果中已有不认识的 `projection` 字段时保留完整原文，不覆盖未知元数据。不能安全外置的内容保持完整，可能提前触发预算停止；不声称任意输入都能压缩成功。
- 一般保存失败返回全量数据与 `evidenceUnavailable`；凭据策略拒绝（sensitive）例外，不把被拒的敏感原始结果回显到新模型消息。已确认成功仍为成功，不把证据失败转成重新执行业务工具。

### 取回与权限

`runtime_read_evidence` 只在当前检查点存在授权引用时提供，能力为本地只读；不调用 Renderer/MCP、不重新执行原工具。工具名冲突拒绝。动态注册写入 `context.evidence_tool_registered`，实际定义亦随下一次模型请求记录。

参数：`evidence_ref`，可选 `path`（JSON键路径）、`offset/limit`、`finding_offset/finding_limit`。limit至多100，findings至多50；各自保留storedTotal/nextOffset与源数据range。默认最大输出16000字符；最多16次确定性缩页且不执行任何业务动作。单条值仍过大时报quota，要求更深path，绝不截断JSON或擅自业务汇总。

授权由检查点的 `contextEvidence` 注册表提供，scope不取自模型参数。注册表绑定application/workspace/**thread**/原run，支持同thread后续run按旧scope取回，不能跨thread借用引用（即使在同一个画板）。S3继续检查凭据、过期、校验和及完整scope。动态工具和模型请求保留现有S4执行账本与总调用预算。

### 历史和协议

保留全部user/assistant/system消息、附件引用、工具参数和匹配结果，不用任意角色摘要代替；仅对可识别的完整旧工具JSON做同一集合外置。无法解析的历史文本原样保留，不把旧截断结果伪装为已修复。每次调用前检查assistant批次与tool结果配对；孤立、重复、未完成批次拒绝发送，最小证据仍超安全预算则有界停止。

代价：长会话可能比旧有损摘要更早停止；这是保护语义的保守策略，并非无限上下文。`boundedSummary`等兼容辅助函数仍在模块中供旧调用方使用，但主Agent Loop已不再用其覆盖历史。

验收覆盖：完整/引用视图确定性答案一致、3000行全部恢复、隐藏问题取回及计数、存储失败、巨大单值/更深路径、未知字段、最小约束超预算、配对拒绝，以及真实模型模拟工具循环取回第999行、跨thread借用引用拒绝、关闭/重启Runtime后沿旧引用读取且原工具计数仍为一次。测试证据和实际完成状态以OpenSpec执行记录为准。S5.3实现与边界见下文，S8发布门禁仍未完成。

## S5.3：模型模态适配

`modalityProjection.ts` 是无宿主依赖的 Kernel 策略：

| 模型 `vision_capable` | 输入策略 |
| --- | --- |
| `true` | 保留已准备的图片附件及视觉工具；这只是已配置能力，不是视觉验收通过 |
| `false` | 不发送图片，移除截图和view_image工具，保留结构化观察/查询 |
| 未声明 / `null` / 旧的非法值 | 视为unknown；与纯文本一样不发送图片，但日志与说明区分未知和不支持 |

未知不是“默认支持”。新模型保存不再补true，普通文本连接测试不改变图片能力；显式true/false配置继续保留。同一身份的非能力编辑保留用户原声明；更换provider/model/base_url/凭据引用时，未重新声明的旧能力失效为unknown。新保存非法非布尔非null能力被拒绝，旧记录读取仍保守识别。不猜测模型名称对应的能力，不擅自换模型。

前端API在调用方未提供能力字段时不再自动写true；模型编辑从旧unknown值回填时也不自动勾选视觉能力。用户显式勾选仍可保存true；已有true配置不批量清空，因为无法可靠区分历史默认值与用户确认。

实际模型调用在中间件补充后、预算检查前进行投影，预算及model.request记录的是最终发送的消息与附件。每次尝试记录纯元数据 `context.modality`（mode/omitted_images/model_id/model_changed=false），不包含图片二进制。重试仍使用同一个模型。

有图片被省略时：

- 不改用户原话/附件引用，不删除历史附件；在请求中加入运行时限制说明，要求只依据文字或结构化证据、不声称查看图片。
- 当前及历史图片均按此处理；可继续执行结构化工具，不因图片能力未知直接废弃整个任务。
- 最终输出强制附加“未向模型发送图片、不能作为已查看或视觉核验通过证明”的说明。不会把省略图片当作视觉检查通过。
- 已配置视觉模型收到明确“不支持图片”错误时沿用原错误处理，记录禁用并停止该次失败请求；不会静默换模型或把格式错误等同于能力缺失。

运行时说明不能保证任意LLM绝不产生错误的自然语言断言，也不代替S6/S7的可信验收门禁；以是否实际发送输入及运行时限制为事实。模型自报“看到了/通过”不构成系统视觉证据。

测试：true/false/unknown纯策略模拟，非法旧能力保守识别、配置保存/文本probe不升级、身份切换失效；真实Loop模拟false/null两种当前+历史图片场景，断言无图片data URL、视觉工具不出现、结构化工具保留、原模型名称未变、最终输出含限制；原有显式视觉输入、Provider拒绝图片和网关格式错误测试继续保留。所有模型网络均模拟，无真实密钥/模型调用。当前构建验收及源码指纹见S5-3执行记录；Node25、GUI、包内和性能仍属S8门禁。
