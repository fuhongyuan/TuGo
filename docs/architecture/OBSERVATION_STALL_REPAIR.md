# 观察阻断与容器标题避让修复

日期：2026-11-03。范围：真实遮挡的自动预防、可靠进展判断、非故障式结束。

## 根因证据

故障运行 `run_68d369ad-46d4-4a45-8355-4020159b4883` 三次报告同一标签遮挡容器标题。
在隔离 Electron 窗口加载只读画板副本，确认遮挡真实存在：连线标签区域与背景容器标题的实际文字区域重叠。
路由与标签布局原先仅避让前景对象，背景容器的标题被遗漏；观察器反而正确看到了问题。
另一方面，停止策略只比较问题数量、类型、对象 ID，不能区分重复读取、真正修复失败和遮挡程度改善，最后抛出通用运行异常。

## 逻辑链路

1. `sceneObstacles` 统一场景障碍：前景图形整体、背景容器的文字区域；容器空白内部仍可通行。
2. 画布、自动路由、连线标签、静态检查、SVG/PPT 导出共用该模型，避免各自遗漏标题。
3. `boardRenderProbe` 读取实际文本 Range 分片，不把 flex 文本容器或多行文字的外接矩形误认为全部可见文字；仍报告真正遮挡与裁切，并附面积比例。
4. 观察控制器比较新鲜、完整、可度量的证据；仅将影响当前问题对象的成功写入视为修复尝试。只读复查、无关修改、未知或过期证据不累计失败。
5. 两次相关修复仍无可测改善时，由产品策略给出 `QUALITY_REPAIR_STALLED`；Agent Loop 关闭排队工具结果，未开始的操作不会执行，不重放既有写入。
6. 结束事件为 `session.completed/status:partial`，质量门禁保持 `passed:false`；UI 显示“修改已保存，质量尚未通过”，不再冒充运行服务故障或验收成功。下轮清除停滞计数，但保留待验收状态。
