# 备份与恢复

[文档目录](README.md) · [English](en/DATA_RECOVERY.md)

## 三种不同的保存方式

| 方式 | 用途与边界 |
| --- | --- |
| 自动保存 | 保存当前画板/会话，不替代独立备份 |
| 版本快照 | 回看或恢复画板版本，不是整个应用的换机备份 |
| 数据库备份 | 保存 App 与 Runtime 数据，附件和密钥需要单独处理 |

## “导出完整备份”的实际范围

在“设置 → 数据与恢复”点击“导出完整备份”，生成 ZIP：

```text
manifest.json
data/tugo.sqlite
data/runtime.sqlite
```

**当前实现不包含图片/文档附件、配置文件和 `runtime-secrets.json`。** 这个界面名称不意味着全量应用归档；不要仅凭此 ZIP 删除原数据。当前界面也不提供将此 ZIP 一键导回整个应用的功能。

诊断包是另一种 ZIP，包含状态、配置摘要和日志，不是可恢复备份。自动脱敏并不保证覆盖任意私人内容，发送前需自己检查。

## 应用内恢复

1. 在“设置 → 数据与恢复”查看 App 和 Runtime 数据状态。
2. 先导出数据库备份；需要保留附件时，再按下面方式留存整个数据目录。
3. 在对应备份列表选择“恢复”，确认后应用会重启。
4. 恢复只针对所选数据库，不保证与另一份不同时刻的数据库完全一致。恢复后检查画板、会话、附件与模型连接。

恢复会替换当前数据，不应在没有副本时试错。

## 保留完整本地副本

在数据页点击“打开目录”确认真实位置，然后**完全退出 TuGo**，复制整个目录到安全位置。通常目录在系统应用数据路径下，但开发版与安装版可能不同，应以界面显示为准。

至少保留 App 数据库、`runtime/`、附件目录、`database-backups/`、配置和凭据文件。它们都可能含有私人信息，不要上传到公开 Issue。

凭据加密与本机用户和数据路径相关，复制到另一台电脑或改变目录后可能无法解密，应准备重新配置。完整目录副本也不是已经支持的自动跨设备迁移功能。

## 应用打不开时

停止反复覆盖或重装数据目录，先备份。保留版本、系统、启动错误与已检查过的日志，通过 [支持渠道](../SUPPORT.md) 求助。不要提交完整数据库或密钥文件。
