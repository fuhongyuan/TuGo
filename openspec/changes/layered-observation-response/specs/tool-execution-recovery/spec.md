# Spec Delta

## Purpose

为工具执行提供可核对的生命周期和有界恢复行为，区别失败与结果未知；在网络波动、取消和重启情况下，避免跨层重试造成重复业务副作用或不可追踪的执行状态。

## ADDED Requirements

### Requirement: 恢复责任与共享预算
系统 SHALL 为调用指定单一自动恢复责任方并共享次数和时间预算；工具内部重试 MUST 计入预算。认证、权限和参数错误不得盲目重试。

#### Scenario: 多层暂时失败
- **WHEN** 可安全重试的调用经过多个执行层并收到限流响应
- **THEN** 按共享预算及 Retry-After 退避，实际尝试总数不超过上限

### Requirement: 未知写结果的保守核对
系统 SHALL 根据可信执行契约决定幂等性与状态查询方式；未知写结果先核对回执。缺少保证时 MUST 升级，不能直接重放；不可信工具自报提示不构成保证。

#### Scenario: 响应丢失
- **WHEN** 写入完成但响应丢失，且存在可信状态查询
- **THEN** 核对已执行状态并继续，实际业务写入仅一次

#### Scenario: 无法核对
- **WHEN** 非幂等写入超时且无状态查询
- **THEN** 报告结果未知并升级，不自动执行第二次写入

### Requirement: 取消与恢复保持执行身份
系统 SHALL 关联调用、尝试和回执；取消后不得启动新重试，晚到结果不得再次应用。重启 SHALL 保守恢复执行状态，不承诺未实现的 exactly-once。

#### Scenario: 取消后晚到响应
- **WHEN** 调用已取消而宿主随后返回结果
- **THEN** 保存可追踪的实际结果，不重启调用或重复应用业务修改
