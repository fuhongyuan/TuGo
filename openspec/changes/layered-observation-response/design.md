# Design

## Context

动机见 proposal.md，开发及验收场景见 docs/LAYERED_OBSERVATION_IMPLEMENTATION_PLAN.md。当前 runtime-ts/src/observation.ts 硬编码画板写工具名及三次写入阈值；runtime.ts 直接组织观察消息；src/lib/boardObservation.ts 使用前端内存保存完整报告。现有上下文估算、异常归类和调用账本需复用，不另造 Agent Loop。仓库尚无主规格，新增 delta 不表示上述能力已经完成分层迁移。

## Goals / Non-Goals

**Goals:**
- 分离采集、诊断、策略、动作与再验证，统一证据并允许本层处理。
- 遵守 Kernel / TuGo Package / Platform 边界，先建立可测试端口，逐步迁移现有入口。
- 保持用户数据、旧工具结果和自定义配置兼容。

**Non-Goals:**
- 不新增独立观察服务、任意插件执行平台或第二套循环。
- 不宣称 DOM 等同于像素/Office 验证，不提供分布式 exactly-once。

## Decisions

### 责任划分优先于文件拆分
Kernel 管调度、预算、通用协议及模型投影；Platform 提供执行恢复和受控存储；TuGo 管几何、修复、目标验收；Renderer 探针只采集实际状态。通过序列化端口通信，无 UI 返回不支持。
选择此方案而非大一统观察中心，避免核心识别图形业务，也避免每个工具复制循环。

### 证据不是模型消息
证据包含身份/来源/范围/版本/执行状态和事实；诊断与动作记录分别关联，生成新的再验证证据，不覆写历史事实。模型视图只保留所需字段与受控引用，不能丢掉完整阻断数量和未检查项。
选择持久证据+投影而非直接截断字符串，以便恢复明细、定位责任和证明压缩未改写执行事实。

### 恢复由单一责任方协调
执行器根据可信契约核对幂等、回执及结果未知。共享 attempt/时间预算覆盖内部重试；取消后不启动新尝试。没有保证的未知写结果升级，不重放。输出检查失败不能撤销已经发生的外部副作用。
拒绝“所有异常统一重试”，避免重复写入和多层次数相乘。

### 领域处理保持任务语义
领域返回明确的完整/分页/部分/汇总状态。明细请求保留明细入口；业务条件变化需要上层授权。只读观察不修复，修复作为独立动作可撤销并复检。
拒绝静默汇总或把自动修复藏进读取。

### 有界生命周期调度而非无边界轮询
按变化/风险/交付触发；等价目标版本请求去重，不同覆盖范围不得误合并。当前版本、会话/渲染环境改变使验收失效；重启保留历史记录但重新核对当前效力。观察失败不重放成功操作。

### 可重复验收
以确定性模拟模型、故障注入和受控 fixture 验证通用行为，查询与绘图共享核心。S1 冻结性能基线，默认无观察路径 p95 回退不超过 10%；记录 p50/p95、内存、输出大小及尝试数。GUI 观察有界并可取消，源码与包内行为分别验证。

## Risks / Trade-offs

- 大结果落盘增加敏感数据与配额风险 → 权限隔离、凭据排除、保留期/配额、明确不可取回。
- 现有代码混合职责且有未提交改动 → S1 记录工作区基线，增量适配，不覆盖已有工作。
- 旧包不识别新存储格式 → 加法迁移、版本校验、旧数据 fixture；不能安全回退时拒绝打开新格式，保留恢复副本。
- token 估算非精确计数 → 预留余量，最小证据仍超限时停止/升级，不无限压缩。
- 探针不具备像素完整性 → 明确 coverage；无 UI、字体/播放不稳定时返回未知。

## Migration Plan

按原计划 S1–S8 推进，tasks.md 是唯一可勾选实施清单；原计划保留分阶段验收条件并链接此变更，不再另计一份完成比例。

先基线，再契约、存储、恢复、上下文与领域接入，最后调度及发布。每任务先补测试，完成后记录命令/退出码/源码指纹/日志并立即勾选。迁移保留旧 API 适配；新增默认项不覆盖用户修改。回退停用新增策略并保留调用账本与证据，不能因回退重放未知写操作。

发布只在隔离 profile 或受控副本验证；不自动覆盖 /Applications，不把未通过门禁转成已知限制后算完成。每批次更新 tasks.md 和执行记录；完整完成后再考虑归档。

## 2026-11-03 Approved Security Scope

用户已批准将完整依赖安全升级纳入本轮，包含进入前端/PPT产物的devDependencies及构建/测试工具主版本变更。禁止使用忽略审计或盲目force降级来验收；保持绘图/导出、用户配置和数据契约，升级后重新执行当前源码及包内全门禁。
