# TuGo 亮点功能演示脚本

这套脚本用于后续真实录制，当前不包含已完成的 GIF 或视频。每条可以独立观看、独立录制。时间是剪辑后的目标时长，不代表 AI 的实际完成耗时。

## 首批录制顺序

先录 **01 AI 画图 → 02 圈选改图 → 04 图片复刻 → 10 聊天交付 PPT**。这四条回答“怎么开始、怎么修改、旧图片怎么办、最后交付什么”。接着录 08/09 的确定性手动导出流程，再补齐导入、问图和图片分享。

每条都要保留独立片尾，不强迫观众先看上一条。README 首屏先选一条主片；其他脚本适合对应功能段落与单独分享。录完再决定是否剪一个总览片，避免把十个操作压进十五秒。

## 共用拍摄规范

- 每条只讲一个主要收益，字幕以脚本中的具体动作和结果为主；无须旁白也能看懂。
- 使用专用演示画板和自制样例。录制前保存初始快照，重拍恢复专用演示内容。
- 统一窗口尺寸，优先录制 1440 × 900 左右的应用区域；发布可缩至约 960–1200 像素宽，以中文字仍可读为准。
- 隐藏桌面杂物和无关内容。字幕放在不遮挡聊天、选区或文件附件的空白位置。
- 每个关键点击留出可辨识的停顿；成片末尾留 2–3 秒展示最终结果。不要用高速鼠标动作代替过程说明。
- 提示词可直接粘贴，不必逐字打字。长等待可跳剪或加速，相关镜头注明“等待已剪短”或实际加速倍数，不用成片时长暗示生成速度。
- 生成类镜头必须来自真实调用。同一条片保留需求、运行、结果的连续原始记录。CLI 可以帮助准备初始素材，不能伪装成片中 AI 的操作。
- 导出类演示必须打开实际生成文件；PPT 演示需展示可编辑对象。只有菜单或“成功”提示不算验收。
- 同时保留原始录屏、MP4 和 GIF；GIF 以清晰为先，尝试控制在 3–8 MB，不能在录制前保证大小。
- 文件建议命名为 `01-ai-draw-zh.mp4` / `01-ai-draw-zh.gif`。录制后在各脚本末尾填写结果和文件路径。

## 已确认的功能边界

- 圈选加入对话用于表达上下文与修改意图，不构成严格的编辑隔离。
- 图片复刻依赖支持视觉输入的模型，并要求图片作为聊天附件上传；目标是结构重画，不是像素级还原。
- Mermaid、PlantUML、draw.io 导入覆盖范围不同。主片先使用基础语法；PlantUML/draw.io 不宣传全格式无损兼容。
- 单区域 PPTX、批量框选 PPTX、聊天生成可下载 PPTX 是三条不同操作链路，各自拍摄。
- 聊天 PPT 在当前源码中有导出工具、生成文件保存和回复附件下载入口；仍需核对运行中的应用版本与模型表现。
